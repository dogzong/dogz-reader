# dogzclaw（原 AI 问答）设备端操作与技术说明

更新：2026-10-04。目标为无触屏的 Waveshare ESP32-S3 ePaper 3.97。

## 当前实现

应用菜单增加「dogzclaw」（原名「AI 问答」），保留录音、本地音乐与既有阅读功能。上下导航沿用系统的 NavPrevious/NavNext 映射；确认选择，返回退出。首页提供语音提问、恢复任务、历史记录、设置及取消任务。

语音提问先显示上传告知，确认后录制最多 60 秒的 16 kHz、单声道、16 位 WAV。首次使用确认自动上传说明后，确认键停止并自动上传识别、提交问答；返回取消本次录音不上传。设置打开转写校对后，识别文字分页显示，确认才提交问答；识别错误可返回重新录音。回答支持分页，历史记录可查看，长按确认并再次确认可删除。回答页确认继续追问，带最近对话上下文；首页语音提问开启新对话。

## 配置与服务器联调

设置中填写 HTTPS 服务地址（默认 https://www.dogzong.com/reader-ai/v1）及 Reader AI 设备令牌。此处不是 DeepSeek API key；上游密钥应保存在服务器。设备令牌保存在板载 NVS，输入框隐藏内容。

在 TF 卡放置 `/.crosspoint/reader-ai-ca.pem`，内容为服务证书的可信 CA PEM，最大 16 KiB。必须使用可信来源的 CA；设备验证证书和主机名，不支持绕过校验。设备时间需先通过现有联网时间同步功能校准。使用「测试连接」检查授权以及 ASR、QA 能力。

服务器需实现 protocol=1 的 `/health`、`/transcriptions`、`/questions`、`/jobs/{id}`、`/jobs/{id}/result?cursor=N` 和 DELETE `/jobs/{id}`。任务状态为 queued/running/completed/failed/cancelled。结果游标按 Unicode 字符数递增，每块文字至多 2048 字节。上传和问答均带幂等键。

服务器已经部署，上下文 DeepSeek 两轮公网测试通过。此前 ASR 上游返回账户余额不足，本轮未重新调用 ASR。最新修复固件已构建、刷入并通过页面回归；录音/MP3扬声器听测和完整中文语音链路仍待验证。

## 存储、资源与恢复

临时音频：`/.crosspoint/voice-assistant/question.wav`；录制中使用 `.part`。识别文字成功保存后删除临时音频。`pending.json` 保存任务 ID、幂等键及识别文字；离开等待界面保留任务，重新进入后选择「恢复任务」。显式「取消任务」才请求服务器取消并清理本地待处理记录。

会话历史存为应用目录下的 JSON 文件，**一次会话一个文件**（见下节）。保存先写临时文件再替换。断电遗留录音 `.part` 不自动恢复。

音频上传使用现有 HTTPS API 所需的连续 PSRAM 缓冲，最大 1,920,044 字节；不足则提示失败。网络响应上限 16 KiB，回答上限 24,000 UTF-8 字节、8,000 字符。后台工作线程栈 16 KiB；页面退出等待线程结束再释放资源，音频和网络操作期间阻止自动休眠。

前台轮询最多 120 秒，超时保留任务供恢复。普通录音不因 AI 功能而上传。日志不输出令牌和提问内容。

## 本地 USB 配置

Waveshare S3 固件支持物理 USB 串口 `CMD:AI_CONFIG <JSON>`，字段为 endpoint、token、ca（可信 PEM）和 epoch（UTC 秒）。命令不回显内容，仅返回 AI_CONFIG:OK/INVALID/FAILED。配置写入 NVS、TF 卡证书及持久时钟；无需将令牌编译进固件。JSON 最大 20 KB，证书最大 16 KB。需退出 AI 页面后执行，再重新进入以加载新配置。

`CMD:AI_HEALTH` 使用已保存的 Wi-Fi 检查设备自身的 HTTPS 健康接口，只返回成功状态和配置能力，不输出认证信息。此诊断会短暂阻塞交互，测试完成后关闭由诊断开启的 Wi-Fi。

USB Wi-Fi 配置：`CMD:AI_WIFI <JSON>`，字段为 ssid 和 password。长度检查后调用既有 WifiCredentialStore 保存，返回 AI_WIFI:OK/INVALID/FAILED，不回显密码；SSID 最长 32 字节，密码为空或 8–63 字节。此入口仅在 Waveshare S3 编译，使用设备现有凭据存储，不把密码嵌入镜像。

## 2026-10-04 流程与上下文更新

首次语音提问显示一次自动上传/问答说明，确认后保存偏好。之后首页确认直接录音，再按确认停止：自动联网识别并提交问答，不再要求确认上传或确认转写。返回键取消录音，不上传。若希望人工核对识别，在连接设置中打开「转写校对」；识别结束后确认发送。

回答页按确认「继续追问」，服务器带上此前完成的问题和回答。首页「语音提问」开启独立新对话；本地历史回答也可继续追问。设备只发送上一轮回答任务 ID，服务器核对同设备归属，最多携带最近 8 轮、6000 字符（旧问题/回答分别最多1000/1500字符），避免无限增长。原服务任务仍为24小时保留，过期历史不能继续追问，应从首页开始新对话。未新增独立会话数据库表，沿用现有任务与幂等存储；旧客户端不传父任务时仍是独立问答。

音频修复：Waveshare ES8311 音量改为幅度到 dB 的换算，45% 对应约 -7 dB，而非此前约 -49 dB。音频应用进入时停止遗留按键提示音，应用内独占共享音频通道。MP3 用两帧流式插值转为16kHz单声道，额外状态为常量大小，不缓存整曲；这是板载16kHz输出，不能保留高采样率音乐的完整高频。录音产生的16kHz WAV不需要重采样。


## 2026-10-04 会话管理（追问追加 / 多会话 / 可继续）

**会话 = 一条 `parent_job_id` 链**，链的根（第一轮提问的 question job id）就是会话 id。

- 存储：`/.crosspoint/voice-assistant/history/<会话根 job id>.json`，**一次会话一个文件**，内容为
  `{"version":2,"root":…,"updated":…,"turns":[{"job":…,"question":…,"answer":…}]}`。追问把新一轮
  `push` 进 `turns` 并**重写同一个文件**，不新建文件。
- 上限（写死在代码里，不是设置项）：**最多 20 轮**（`kMaxTurns`，超出丢最旧的）且**单文件 ≤64 KB**
  （`kMaxDocBytes`）。超过 64 KB 时的降级顺序：先丢掉最旧若干轮的 `answer` 文本（`question` 与 `job`
  保留，所以列表轮数和会话链都不变）→ 仍超则从最旧开始整轮丢弃 → **最新一轮永不丢弃**，只把它自己的
  文本按预算折半直到放得下。所以最新回答总是完整的。
- 历史列表：**一行 = 一次会话**，标题是首轮问题，副标题是「共 N 轮 · MM-DD HH:MM」（时钟未校准只显示
  轮数）。长按确认仍可整场删除。
- 继续对话：选中一行后把 `parent_job_id` 指向该会话**最后一轮**的 question job id，服务端据此沿链回溯，
  所以从历史进入的追问带着这段会话的上下文；追问继续写入同一个文件。
- 屏幕：转写页/回答页把**本次会话累积渲染**成对话记录，用户提问右对齐、回答左对齐，沿用原来的分页与
  左右导航；打开会话时停在最新一轮，往回翻可看之前轮次。整场会话最多渲染 1024 行（`kMaxTranscriptLines`），
  超出只保留最新部分，以保证分页一定成功。
- 旧格式（每条回答一个文件）：**不删除、不改名**。读取时按「只有一个 turns 之外的顶层 question/answer/job」
  识别为单轮会话（`job` 缺失时用文件名兜底，也就是那条回答的 job id，因此仍可作为继续对话的父节点）；列表里
  仍是一行。第一次追问时该文件会被就地升级为 v2 会话文件（保留文件名 = 会话根），此后一切照常。损坏、截断、
  类型错误、文件名非 32 位十六进制、非 UTF-8、根不是 job id、超过 64 KB 的记录一律**跳过该条**，不影响其它
  会话，也不会崩溃。

主机回归：`scripts/tests/test_voice_conversations.py`（存储层用内存假文件系统编译真实的
`VoiceHistory.cpp`，逐字节断言会话文件、上限、聚合与继续链）。
