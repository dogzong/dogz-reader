# 录音、音乐与 dogzclaw（原 AI 问答）：操作和 UI 方案

状态：开发中，2026-10-03。Waveshare 3.97 音频应用已有 WAV 录音/回放、MP3 流式解码接入、文件列表、删除确认和切歌代码。固件已串口直刷，串口日志确认 CrossMux UI 和原有中文 EPUB 可正常启动/加载；MP3、麦克风和扬声器效果尚未实测。设备端 AI 应用与网络客户端未实现；服务器工作按用户要求暂缓，不在此记录公网服务的当前状态。

当前录音版本以确认键开始、再次确认或返回键停止保存，最多录制30分钟，先写入 `/Recordings/*.wav.part`，停止后补齐 WAV 头并替换为 `.wav`；遇到重名时不会覆盖旧录音。断电遗留的 `.part` 暂不自动恢复，需通过通用文件管理查看或清理。录音列表可选择并回放 WAV；音乐页面扫描 `/Music/` 中最多200个 WAV/MP3 文件。MP3 解码代码会跳过 ID3v2 标签并把 PCM 送入现有音频 HAL，但还未用真实 CBR/VBR 文件实测。列表长按确认键并二次确认后删除文件；播放时左右键切换曲目；首页不扫描 TF 卡剩余容量，以避免进入页面时阻塞。暂停和用户可调音量、设备端 dogzclaw 仍未实现。

## 入口与界面原则

保留现有应用菜单及可见性设置，追加“录音”“本地音乐”“dogzclaw”，与微信读书、AirPage同级。新应用内返回键回到应用菜单。沿用CrossMux当前主题与中文字体，所有新增界面文字走翻译系统。

设备没有触屏，所有操作必须能用逻辑方向、确认、返回键完成。底部提示随状态变化，不改变原有电源键、功能键双击或长按语义。一轮按下/松开只触发一次操作，页面跳转消耗继承的按键释放。

采用黑白高对比、大文字、固定布局和分页列表。以竖屏480×800作线框示意，代码依据当前方向和主题安全区域布局，支持横屏；不硬编码屏幕尺寸。选中项反白，图标配文字，不用灰色区分唯一状态。

录音计时建议每5秒更新、播放计时每10秒更新；开始、暂停、停止、错误立即更新。无滚动波形、旋转等待动画、跑马灯和逐token回答。优先局部更新，残影清理交给既有显示策略并实测调整。

## 录音与音乐

```text
│   我的录音             12 条 │
│   本地音乐             38 首 │
│                              │
│ TF 卡可用空间：…             │
│                              │
│ 方向：选择  确认：进入  返回  │
└──────────────────────────────┘
```

### 录音与回放

1. 进入“开始录音”，显示“录音仅保存在本机”，确认后开始。
2. 录音页显示“正在录音”、已录时长、剩余空间、静态录音标记和“停止并保存”。不播放按键提示音。
3. 确认停止并保存，显示文件名、时长，以及“回放 / 再录一段 / 返回”。返回键也停止并保存，避免误丢内容；删除在文件操作中单独确认。
4. “我的录音”按新到旧分页显示，选择后可回放、删除。暂停/继续属于回放，首版录音不做中途暂停拼接。
5. 文件拟保存在 `/Recordings/日期/时间-唯一编号.wav`；RTC无效时用唯一编号，不覆盖旧录音。可通过原有文件传输取回。

无卡、卡满或写入失败时明确显示原因；停止录音并尽可能保存已有完整数据，不显示虚假的“保存成功”。非正常断电后的可恢复录音在下次进入时标为“已恢复，末尾可能不完整”。

### MP3播放

1. 通过原有USB Drive或Wi-Fi文件传输把MP3放入 `/Music/`。
2. 打开“本地音乐”，按文件夹分页浏览，不一次扫描整张TF卡。
3. 确认歌曲进入播放页；先显示文件名，解析成功后显示歌曲信息。

```text
┌──────────────────────────────┐
│ 本地音乐                 3/38│
│                              │
│ 歌曲名称                     │
│ 艺术家（缺失则不显示）       │
│                              │
│ 正在播放     01:20 / 04:32   │
│ ━━━━━━━─────────────         │
│                              │
│ > 暂停                       │
│   上一首     下一首           │
│   音量：30%                  │
│                              │
│ 方向：选择  确认：执行  返回  │
└──────────────────────────────┘
```

控件在实现中按可导航行排列，不能依赖点击。方向键选择动作，确认执行；音量进入单独调节页，方向调整、确认保存、返回取消。避免让同一方向键同时承担换曲和调音量。

首版离开播放页停止播放，保存当前文件与可恢复位置；精确VBR定位未完成时只恢复文件，不伪称恢复精确秒数。返回阅读后正常节能。坏文件、格式不支持显示可跳过提示。删除正在播放的文件前先停止。

## AI问答

首次在设备配置网页设置服务器HTTPS地址与设备Token，点击连接测试。服务器持有DeepSeek和ASR密钥；设备只显示连接状态，不回显秘密。

```text
应用 → dogzclaw
          ├─ 新问题
          ├─ 最近对话
          └─ 服务状态

新问题 → 确认开始录音 → 确认结束（最多60秒）
       → 上传并识别 → 查看转写文字
       → [发送问题] / [重新录音] / [取消]
       → 正在生成 → 中文回答分页
       → [继续追问] / [返回问题] / [返回列表]
```

录音前明确提示“本次录音将发送到语音服务识别”。识别完成后由用户确认才向DeepSeek发送文字。首版不依赖复杂中文键盘，错误转写通过重新录音修正；网页编辑可作为后续增强。

回答页：顶部显示简短问题和页码，主体使用现有中文渲染与分页，底部显示“上一页 / 下一页 / 操作”。长回答保存到卡，不将整段历史长期放RAM。列表、标题、代码块做适合窄屏的文本转换，不以截图显示答案。

记录拟保存在 `/.crosspoint/voice-assistant/`，含版本号、会话ID、问题、回答及时间；每次保存使用临时文件替换，历史分页加载。AI临时音频与普通录音分目录，成功后默认删除临时音频，失败时仅保留供重试并允许用户删除。历史只在进入AI应用时联网，阅读时不后台轮询。

| 状态 | 页面与操作 |
|---|---|
| 未联网 | 连接Wi-Fi后重试；不丢本次录音 |
| ASR不可用 | 保留录音，重试或退出，不调用DeepSeek |
| 识别为空 | 提示未识别人声，重新录音 |
| Token失效 | 引导配置网页重新配对，不反复重试 |
| 额度用尽 | 显示服务限额，停止自动重试 |
| 等待超时 | 显示任务已保存，稍后查看；不重新创建同一请求 |
| 用户取消 | 停止设备等待并请求服务器取消；已发送上游请求可能仍产生费用 |
| 存储失败 | 明确提示无法保存历史，不能假装已保存 |

## 原有功能与使用边界

中文阅读、微信读书、AirPage和所有原应用保留原操作。已有待办和便签继续由Linux推送到AirPage，不增加重复入口。

首版不做边读边听和自动朗读。进入USB Drive或执行系统关机前先终止音频并保存。录音/播放期间暂时不响按键声，退出后恢复原提示音配置。

## 用户验收路径

1. 原来常用的中文书和微信读书仍正常打开，进度、字体与主题未丢失。
2. 断网状态录制1分钟语音、保存、回放；用电脑取回WAV确认内容。
3. 放入中文文件名的CBR/VBR MP3，验证播放、暂停、切歌、音量和退出。
4. 中文语音提问，核对识别文字后发送，分页查看DeepSeek回答并追问。
5. 断网、卡满、坏MP3、服务错误时可返回阅读，不重启循环、不丢已有书籍。
6. 原AirPage推送继续工作；音频应用反复进入退出后提示音、电源和文件传输正常。

部署和固件技术细节见 [技术方案](audio-voice-plan.zh-CN.md)。
